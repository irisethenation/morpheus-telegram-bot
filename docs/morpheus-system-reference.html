System Architecture

Morpheus runs as a two-layer system: Vercel handles all inbound HTTP (Telegram webhook, payment webhooks, lead forms) and OVHCloud hosts the AI core (FastAPI, 69 skills, PostgreSQL, Redis, Qdrant).

Vercel — Serverless

Webhook Layer

Receives Telegram messages, payment events, lead form submissions. Routes to OVH for AI processing. Hosts static GEM landing page.

OVH · 51.79.29.15

FastAPI with 69 skills. Manages agent memory, property pipeline, CRM, email dispatch via ox.livemail.co.uk. PostgreSQL morpheus_core DB.

OpenRouter

LLM Router

Dolphin (uncensored) for legal/mortgage/property. Gemma 3 27B for general conversation. OVH Morpheus as fallback if OpenRouter unreachable.

Agent Hierarchy

Root Sovereign

Morpheus

Master AI. Manages all verticals: property, websites, trust, academy. Routes via OVH FastAPI (port 19000).

Dispatcher

Trinity

Batch outreach. Decomposes task lists into atomic single-skill sub-agents. Activates Ruflo swarm for 50+ simultaneous sends.

Security

Mapondera

Scans for exposed credentials every 6h. Manages secret rotation. Spawns sub-agents (one skill each). Activates Ruflo for 3+ parallel skills.

Swarm

Ruflo

Parallel task execution engine. Spawns N sub-agents simultaneously. 120s timeout. Activated by Trinity or Mapondera.

Spawning Rules

Batch SizeDispatcherMethod
1–2 skillsMaponderaDirect sub-agents, sequential or pairs
3+ skillsMaponderaRuflo swarm activation
Under 10 contactsTrinityDirect sub-agents
10–49 contactsTrinityGroups of 10, staggered 5s
50+ contactsTrinity → MaponderaRuflo swarm
⚠️ Credential Rule
No agent stores credentials. Trinity receives them as task payloads from Mapondera's secure store, uses once, discards. All secrets live in /opt/stacks/morpheus/.env (OVH) or Vercel dashboard.

Invoice & Payment Commands

Every payment is pre-traced before it arrives. Create an invoice → give the client the IRISE-XXXXXXXX reference → they include it on their bank transfer → Morpheus matches it automatically.

/invoice
Create a new invoice. Generates a unique IRISE-XXXXXXXX reference that the client uses on their bank transfer.
/invoice 2500
/invoice 5500 John Smith
/invoice 12000 Smith Estates john@smith.com
/invoices
List the last 15 invoices with status (✅ paid / ⏳ pending / ❌ cancelled).
/invoices
/pending
Show all pending invoices awaiting payment. Use this to check what's outstanding.
/pending
/pay_status [ref]
Look up any invoice by its IRISE reference. Shows amount, status, client, and paid timestamp.
/pay_status IRISE-A83F91C2
/log_payment [amount] [ref]
Manually record a payment. Use this when a webhook isn't set up yet, or to confirm a Tide transfer you can see in your app. Fires the full matching pipeline — agents trigger if matched.
/log_payment 2500 IRISE-A83F91C2
/log_payment 5500 IRISE-B92E3F1A John Smith

Add PAYMENT_DB_URL to Vercel dashboard and run the migration once:

Stripe Payload Handling

The Stripe webhook handles two payload formats automatically:

FormatStructureReference Location
Snapshot (recommended) event.data.object = full Stripe object event.data.object.metadata.reference
Thin (new Event Destinations) event.data = minimal reference only Falls back to fuzzy match on amount + time
✅ Recommended: Enable snapshot payloads
In Stripe Dashboard → Developers → Webhooks → your endpoint → toggle "Send snapshot data". This ensures 100% reference matching from Stripe payments.

09

Database Tables (morpheus_core)

All payment tables live in the morpheus_core PostgreSQL database on OVH. Run once to create: psql $POSTGRES_URL -f db/001_payment_tables.sql

TablePurposeKey Fields
invoices Every invoice you create before payment arrives id UUID · reference IRISE-XXXXXXXX (unique) · amount · status (pending/paid/cancelled) · client_name · client_email · lead_id
transactions Raw inbound payments from all providers — immutable on insert id (provider's own ID — guarantees idempotency) · provider (tide/stripe/crypto/manual) · amount · reference · raw JSONB · processed
payment_matches Anti-replay audit log — one row per matched transaction/invoice pair transaction_id (unique) · invoice_id · confidence 0–100 · match_type (reference/fuzzy/manual)
revenue Immutable ledger of all confirmed revenue events lead_id · invoice_id · transaction_id · total_value · stream (websites/property/trust/academy)
affiliates Affiliate partners — ledger only, no auto-payout name · email · code (unique) · rate_pct default 10%
affiliate_earnings Earned commissions pending manual approval affiliate_id · invoice_id · amount · status (pending/approved/paid/rejected)

Useful Queries

-- All paid invoices this month
SELECT reference, amount, client_name, paid_at
FROM invoices WHERE status = 'paid'
  AND paid_at > date_trunc('month', NOW())
ORDER BY paid_at DESC;

-- Unmatched transactions (need manual matching)
SELECT id, amount, reference, sender_name, created_at
FROM transactions WHERE processed = FALSE
ORDER BY created_at DESC;

-- Revenue by stream
SELECT stream, SUM(total_value) AS total
FROM revenue GROUP BY stream ORDER BY total DESC;

-- Confidence distribution of all matches
SELECT match_type, AVG(confidence)::int AS avg_confidence, COUNT(*)
FROM payment_matches GROUP BY match_type;

After deploying to Vercel and setting TELEGRAM_BOT_TOKEN_MORPHEUS, register the webhook once:

https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<vercel-preview-url>/api/webhook

Verify it's registered: https://api.telegram.org/bot<TOKEN>/getWebhookInfo
